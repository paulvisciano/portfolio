The Premise

To see why this matters, go back to where jailbreaking began. Back then the lock was physical — a phone locked to one carrier, sealed by firmware, and the only way out was to crack the firmware itself. In the summer of 2007, a seventeen-year-old named George Hotz — geohot — spent five hundred hours soldering and coding to unlock the original iPhone. He posted the video from his parents' kitchen: "This is the world's first unlocked iPhone." It was breaking news. The New York Times, CBS, CNBC, Wired — the story spread across the world in a weekend. He traded one of the unlocked phones for a Nissan 350Z. He was still a teenager.

Today the lock isn't the phone. It's the operating system on the laptop you use every day — the vendor's assumptions baked into the software, deciding what runs, what phones home, what you can change. Jailbreaking your laptop is the same idea: crack the lock the vendor shipped, on whatever machine you have. Mac, PC, or a Linux box you already run.

The payoff is transparency and editability. On a locked OS you can still inspect processes — the difference is what happens next. On Omarchy you get a curated, minimal set of services you chose, no vendor telemetry baked in by default, and the ability to override everything through AI. Something not working? Describe it and the local model rewrites the config. Don't like how it looks? Ask for a custom theme. A game that won't launch, a driver that misbehaves — those become easily tweakable through conversation, with every change visible and reversible. The lock you cracked becomes a machine you can talk to.

This is the roadmap to sovereignty. Every layer already works. Follow the steps and you end up with a computer that is truly yours.

  • GitHub — your source of truth. github.com
  • A domain registrar — Namecheap, Cloudflare, Porkbun, etc.

Part 1 — On the OS

Crack the lock the vendor shipped. Replace their assumptions with an OS you control.

Official Getting Started — omarchy.org/manual/getting-started

From the Omarchy manual, condensed:

  1. Omarchy is installed using an ISO. Choose a full-disk install (takes over the entire drive) or a free-space install (unallocated space — how you dual boot alongside Windows or another OS; turn off BitLocker in Windows first).
  2. The installation defaults to full encryption. The full-disk option wipes the selected drive — back up first.
  3. Download the Omarchy ISO from omarchy.org, put it on a USB stick (balenaEtcher on Mac/Windows, caligula on Linux), and boot off the stick.
  4. You must turn off Secure Boot and/or TPM in the BIOS. They're Microsoft security schemes meant for Windows and Microsoft-affiliated Linux distributions.
  5. Answer the configuration questions, confirm them, select a drive, and watch the install. Under a minute on fast machines, no more than five on older ones.
  6. Now you're ready to Omarchy.

Use a wired or 2.4 GHz keyboard — full-disk encryption won't accept a Bluetooth keyboard at startup. Encryption is on by default for a reason: you don't want anyone with access to your hardware to get your data. Hit Ctrl+C on the first screen to prepare the machine for another owner, or on the disk-formatting screen to install without encryption.

Do this

  1. Download the ISO from omarchy.org (or the direct ISO at iso.omarchy.org).
  2. Flash it to a USB stick (balenaEtcher on Mac/Windows, caligula on Linux).
  3. Boot off the stick. Turn off Secure Boot / TPM in BIOS.
  4. Follow the configurator — full-disk or free-space install, encryption on by default.
  5. Reboot. List every process, every service, every connection. You chose all of it.

Part 2 — Run Your Local AI

Give the stack a brain. Three surfaces, one machine.

📷 Replace with: two devices hitting the same localhost assistant + server throughput log.

Do this

  1. Get llama.cpp set up. It ships with its own UI — good enough to talk to a model right away. github.com/ggml-org/llama.cpp
  2. Pull a model: Bonsai. Start with the 8B Q1_0 GGUF from huggingface.co/prism-ml/bonsai. Serve it with llama.cpp on port 8080 — OpenAI-compatible, no API key.
  3. Set up Open WebUI and point it at that same local endpoint. This is the daily workspace — chats, notes, search.
  4. If you want the Knowledge Graph, use my custom fork of Open WebUI that includes it: github.com/paulvisciano/open-webui. The Graph lives under the Graph menu — chats as cards on a canvas, time as space, no cloud.
  5. Expose everything over Wi-Fi. Bind to your LAN IP. Now you can access your local AI from any device on the network — phone, laptop, tablet.

Part 4 — Create Your Own Site (The Public Layer)

Claim a domain, push a repo to GitHub, let Vercel deploy on every push, then wire the domain in. This is the public face — not the brain. The brain stays local. The internet gets a site you chose.

📷 Replace with: Vercel project with green deployment + domain status "Valid Configuration".

Do this

  1. Buy a domain at your registrar.
  2. Create a GitHub repo, push your site.
  3. Import the repo into Vercel — it deploys on every push to main.
  4. In Vercel → Settings → Domains, add your domain. Set the A record (apex) or CNAME (subdomain) at your registrar.
