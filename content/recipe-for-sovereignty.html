The Ingredients

  • Omarchy — the owned OS. omarchy.org · ISO: iso.omarchy.org · github.com/omacom/omarchy
  • Bonsai — the local AI brain (1-bit, ~1.15 GB for 8B). prismml.com · docs.prismml.com · huggingface.co/prism-ml/bonsai
  • llama.cpp — the runtime. github.com/ggml-org/llama.cpp (PrismML fork for ternary: PrismML-Eng/llama.cpp)
  • Vercel — deployments. vercel.com
  • GitHub — your source of truth. github.com
  • A domain registrar — Namecheap, Cloudflare, Porkbun, etc.

Step 1 — Take Over the OS

Crack the lock Apple (or whoever) shipped. Replace their assumptions with an OS you control. Geohot did it to firmware in 2007; you do it to the whole stack today.

📷 Replace with: Omarchy desktop screenshot after first boot.

Do this

  1. Download the ISO from iso.omarchy.org.
  2. Flash it to a USB stick (balenaEtcher on Mac/Windows).
  3. Boot off the stick. Turn off Secure Boot / TPM in BIOS.
  4. Follow the configurator — full-disk or free-space install, encryption on by default.

Give me the exact commands, the BIOS settings to change, and what to do if the installer complains about Secure Boot. Then verify the install with `omarchy --version`.

Step 2 — Fork or Build Your Apps

Now that the machine is yours, the apps stop being products you rent. Fork open code, customize it, or build from scratch. Everything runs on localhost — no API keys, no cloud, no usage meter.

Do this

  2. Point it at localhost instead of a hosted API.
  3. Run it. No account, no subscription, no telemetry you can't refuse.

Step 3 — Build Your Own Website (Your Portal to the Internet)

Claim a domain, push a repo to GitHub, let Vercel deploy on every push, then wire the domain in. You now have a public face that lives on hardware and infrastructure you chose.

📷 Replace with: Vercel project with green deployment + domain status "Valid Configuration".

Do this

  1. Buy a domain at your registrar.
  2. Create a GitHub repo, push your site.
  3. Import the repo into Vercel — it deploys on every push to main.
  4. In Vercel → Settings → Domains, add your domain. Set the A record (apex) or CNAME (subdomain) at your registrar.

Prompt an AI to set it up

Confirm with curl that https://example.com returns 200.

Step 4 — Your Local AI Layer

The knowledge graph is the personal assistant that runs on your machine. Phone and laptop talk to each other over your own Wi-Fi — no account sync, no cloud relay. Bonsai 8B fits in about 1.15 GB; on an 18 GB Mac it leaves room for everything else.

📷 Replace with: two devices hitting the same localhost assistant + server throughput log.

Do this

  1. Get a Bonsai GGUF from huggingface.co/prism-ml/bonsai (start with Bonsai-8B-Q1_0.gguf).
  2. Run it with llama.cpp: ./llama-server -m Bonsai-8B-Q1_0.gguf -c 0 --port 8080.
  3. Point your knowledge-graph app at http://localhost:8080. Expose it on your LAN IP so the phone can reach it.

Prompt an AI to set it up

No cloud, no API keys.

Step 5 — Graduate to Creator

Stop forking. Build your own app from scratch, publish it to your domain, and the loop closes: customize, publish, own. This is the moment you stop following the tutorial and start owning the stack for real.

Do this

  1. Scaffold a new app (any stack you like).
  2. Wire it to your local AI layer from Step 4.
  3. Push to your GitHub repo — Vercel deploys it to your domain automatically.
