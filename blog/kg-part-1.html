Knowledge Graph, Part 1: The canvas and the stack

Cut over to an infinite canvas, make time a depth axis, and run models that never leave the machine.

Knowledge Graph started as a bet that memory should be a place, not a thread. The first solid version of that bet was a Three.js infinite canvas with time as a navigable dimension, local models for vision and speech, and a pipeline that kept originals on hardware you own.

Why a canvas

Lists and chat windows flatten life into sequence. A spatial surface lets the same day hold photos, notes, and later conversations without forcing them into a single scroll order. Zoom out for months; zoom in for a afternoon. The camera is the primary navigation, not a sidebar of folders.

Local by default

Models run on Metal. Whisper, vision, embeddings, and the graph stay on the machine. USB transfer preserves EXIF. There is no obligatory cloud ingest to make the product work — cloud is optional, not the path of least resistance.

Sovereignty is the product constraint: if it only works when a vendor’s API is up, it is not a private memory system.
