The published demo is not the product

Local-first apps live or die on the details the public site never has to get right. Conversation state is one of them.

Knowledge Graph is a private spatial memory engine. Conversations, photos, and voice notes float as time layers on an infinite Three.js canvas. Inference runs through Llama.cpp. Retrieval uses LightRAG. The published version lets anyone open a browser and see the shape of the system. The real product is the copy that runs on your machine — offline, zero API keys, data that never leaves the device.

That distinction only holds if the private copy is trustworthy. This week’s commits were not a new model or a new tool. They were conversation state.

A demo can look good while the interface quietly lies about which messages belong to which thread. A local-first product cannot.

What broke and what was fixed

When you switched conversations the panel risked flashing the previous thread’s messages until the async load finished. Sync could overwrite created-at timestamps and make conversation nodes vanish from the canvas. A sync PUT that was meant to keep devices aligned could delete messages the client had not yet received. Active conversation nodes could be buried by photo nodes at similar depth.

Those paths are closed. There is a loading overlay so the panel never shows the wrong messages. Conversation state is preserved across switches. Sync no longer wipes history. The active node stays visible. Auto-flyTo is suppressed for a short window after you deliberately navigate away so the camera does not yank you back.

None of this is glamorous. All of it is required if you are going to trust the system with years of personal history.

Why local-first demands this work

Cloud products can hide messy state behind a spinner on someone else’s servers. The data already left the device; the vendor owns the consistency problem. A local app has to get the details right on hardware you control. If switching conversations shows the wrong messages, or a background sync erases part of a thread, the offline promise becomes theater.

The same principle applies across the Sci-Fi Labs stack. Where is Paul? is the public-facing spatial life map — globe, timeline, stories — that can feed moments into the private graph. Both are just websites, so they open in any browser, including Apple Vision Pro and other AR/VR headsets. The published surfaces are demos. The private clones are the products that keep the data local by design.

The offline test still wins

Unplug the network. Switch conversations. The messages that appear should belong to the thread you selected. Ask about last month; the canvas and the answer should still be correct. That is the only proof that matters. Everything else is marketing.

The published demo shows what is possible. The private clone is what you actually use. Local-first means the interface never lies about your data.
