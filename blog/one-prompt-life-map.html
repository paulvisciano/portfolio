One prompt. Your own life map.

Paste this into Grok, drop your Google Maps Takeout, and get a personal Where is [You]? — globe, timeline, markers, the works. The same idea behind Where is Paul?, now copy-paste ready.

Your location history is already sitting there

Google Takeout will give you years of Timeline data if you ask for it. Most people never open the file. It sits as a zip of JSON, full of places, timestamps, and the quiet record of where a life actually moved. The usual next step is nothing — or a spreadsheet, or a map that never becomes a product you can return to.

Where is Paul? started from the opposite decision: treat that record as first-class material for a spatial app. Globe, timeline, stories, filters. A navigable surface instead of a dump. The live version lives at paulvisciano.com/apps/where-is-paul. It is the proof that the pattern works.

The next step is making the pattern portable. One prompt. Your export. Your name on the title bar.

Copy the prompt below. Paste it into Grok. When the app is ready, drop in your Google Maps Timeline export. That is the entire workflow.

The prompt

Everything below the line is meant to be copied as-is. Change the name if you want; leave the rest alone on the first run.

Build a complete static web app called "Where is [My Name]?" that visualizes personal location history from a Google Maps Timeline export.

Requirements:
- Interactive 3D globe (Three.js) with markers for places stayed
- Timeline scrubber that filters the globe by year or month
- Click a marker to see place name, date range, and a short note
- Simple tag filters (beach, city, nature, etc.)
- Dark, minimal, sci-fi aesthetic — clean spatial UI, not a dashboard
- Accept a Google Maps Timeline / Location History Takeout JSON client-side (file drop or file picker)
- Parse the export, extract significant stays, cluster nearby points, and auto-populate the globe and timeline
- Include a "Load sample data" button so the app demos immediately without any file
- Single page or small set of static files only — no backend, no API keys, deployable anywhere

Make the code clean, commented, and ready to open in a browser. Prefer modern vanilla JS + Three.js. If you need a starter structure, keep it minimal.

That is the whole ask. Grok builds the app. You feed it the export. The result is a personal life map that runs in the browser.

Why this works

The hard parts of a spatial life map are the data model and the interaction model — how stays become markers, how time becomes a filter, how the globe stays readable. Those pieces are now described clearly enough that a single well-structured prompt can produce a working first version. The Google export is the fuel. Everything else is pattern matching against an existing reference (Where is Paul?) and ordinary web technology.

You still own the data. The export never has to leave your machine if you run the generated app locally. The published Where is Paul? site is the public demo; the private copy of the same idea, built from your Takeout, is the version that actually belongs to you.

What to do next

  1. Copy the prompt above.
  2. Paste it into Grok (or any capable coding model).
  3. Download your Google Maps Timeline from Takeout if you do not already have it.
  4. Drop the JSON into the generated app.
  5. Open the result in a browser. Iterate on the UI or data cleaning as needed.
